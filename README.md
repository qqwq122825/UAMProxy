v1.126.2 起：01 阈值大于 0 且录满后只阻断录制口 3366，重放口 3366 继续，与「补数据模式」无关。补数据关闭时重放只走现有热规则，不从录制池插 80xx；录制 01 与重放 01 是两条独立上报。
v1.126.3：「01只收录」勾选后，阈值录满时录制口 01 上行只入池不转 ACE，客户端 TCP 不断。下行真包不丢；本地补短 08 会推进外层序号，ACE 再下发时把序号接到本地心跳后面再转。ACE 若因收不到 01 断开，也只维持客户端，除非客户端自己断开。

v1.128.5：「全额重建」关闭时，不判断设备关系，固定只补中央官方九类。开启后，长样本报告2的`model/ver`用于早期初筛，报告8的`iDevHwModel/iDevSysVer/iDevIDFV`用于确认物理设备；同设备玩家层按录制slot与相对时间补齐十二类，其中`800D`重建轮次，`802C`的`+0x20`按绝对时间差推进、`+0x24/+0x28`按四步链计数，`802A/802B`等待对局触发后再补发。设备信息仍在收集时玩家层保持等待；跨设备继续只补中央九类。玩家录制缺项或Hook漏出Live时进入二级热规则。

每次启动创建一个AI日志运行目录。目录只使用JSON/JSONL，字段类型、文件名和schema由`manifest.json`固定。

- `replay_events.jsonl`：事件、决策、会话时间、模型revision和四类offset。
- `replay_groups.jsonl`：输入/模板/影子/输出逻辑组，原生与补发报告分行。
- `replay_leaves.jsonl`：逐叶原始Hex、ID、序号、slot、长度及语义处置。
- `record_*`：录制物理帧、报告、叶和会话生命周期。
- `stream_frames.jsonl`：包含42B加入帧在内的收发帧。

录制管理中的“导出”当前统一导出玩家设备录制池，导入后按设备特征优先、游戏ID回退参与重放。
