# DFMProxy v1.121：01消息ID与字段差分脚本

## 1. 目的

`tools/compare_01_message_ids.py` 把第一份录制作为基线A，把第二份录制作为检查B，自动完成：

1. 统计每个消息ID的原始出现次数；
2. 按已解密Type9包数换算每100包频率，减小录制时长差异的干扰；
3. 标记B新增、B缺失、频率明显变化及新长度；
4. 在相同 `record_code + message_id + length` 内逐字段比较；
5. 优先标记“基线恒为0、检查数据出现非0”的候选字段；
6. 同时输出人读报告、CSV和完整JSON，便于继续筛选。

## 2. 推荐录制目录

### 2.1 通用原始数组模式

脚本的通用入口是两个普通文件：

```text
本次比较/
├─ 数据1.py
└─ 数据2.py
```

`数据1.py` 作为基线，内容是所有完整01原始帧：

```python
数据1 = [
    [1, 0, 0, 0, 123, 0, 0, 1, ...],
    [1, 0, 0, 0, 98, 0, 0, 2, ...],
]
```

`数据2.py` 写法相同。也支持直接省略变量和最外层列表：

```python
[1, 0, 0, 0, 123, ...],
[1, 0, 0, 0, 98, ...],
[1, 0, 0, 0, 106, ...]
```

每个内层列表表示一个完整原始字节串，元素支持无符号 `0..255`，也支持Hook工具常见的有符号 `-128..127`。输入也可使用：

- JSON数组；
- Python列表或元组；
- Hex字符串，例如 `"010000007B..."`；
- `{"frames": [...]}`、`{"packets": [...]}` 或 `{"data": [...]}`；
- 单帧、多分片帧、一个TCP块中连续放置的多帧、直接Type9片段。

在“本次比较”目录执行时，脚本会自动找到两个中文文件：

```powershell
python D:\DFMProxy\tools\compare_01_message_ids.py
```

也可指定目录或两个文件：

```powershell
python tools\compare_01_message_ids.py D:\captures\本次比较

python tools\compare_01_message_ids.py `
  D:\captures\本次比较\数据1.py `
  D:\captures\本次比较\数据2.py
```

英文文件名 `data1.py`、`data2.py` 同样会被自动识别。

### 2.2 项目日志目录模式

每次实验单独保存一份目录：

```text
CompareRun/
├─ A_clean/
│  └─ 01RecordPackets/
│     └─ test_01_message_leaves_*.jsonl
└─ B_test/
   └─ 01RecordPackets/
      └─ test_01_message_leaves_*.jsonl
```

父目录恰好有两份可识别数据时可自动配对：

```powershell
python tools\compare_01_message_ids.py D:\captures\CompareRun `
  --label-a clean --label-b test
```

也可显式给两个路径：

```powershell
python tools\compare_01_message_ids.py `
  D:\captures\A_clean\01RecordPackets `
  D:\captures\B_test\01RecordPackets `
  --label-a clean --label-b test
```

第一份路径始终是基线A。目录中若含多个 `test_01_message_leaves_*.jsonl`，脚本会把它们合并；因此一次实验保留一个独立目录最直观。

## 3. 支持的输入

按优先级自动识别：

1. `数据1.py` / `数据2.py` 等通用原始01数组文件；
2. `test_01_message_leaves_*.jsonl`；
3. `test_01_sliced_*.log` 或整个 `01RecordPackets` 目录；
4. `01_replace_events.jsonl`；
5. `v117_recording_pools.json`。

v1.121新增的 `test_01_message_leaves_*.jsonl` 是推荐格式。它不受 `detail_01_log` 开关影响，每个已解密Type9报告一行，并保存：

- 时间、会话、账号和报告序号；
- 每个叶子的路径；
- `record_code`、`message_id`、长度和叶子序号；
- 完整叶子 `raw_hex`。

旧的 `test_01_sliced_*.log` 在详细日志关闭时只保存摘要和HEAD，那类历史行缺少完整密文，脚本会给出读取警告并跳过；带完整Hex的历史日志仍可直接分析。

## 4. 常用命令

只检查 `0x0207`：

```powershell
python tools\compare_01_message_ids.py A B --message-id 0x0207
```

同时检查多个ID：

```powershell
python tools\compare_01_message_ids.py A B `
  --message-id 0x0207 --message-id 0x8024 --message-id 0x8029
```

指定输出目录：

```powershell
python tools\compare_01_message_ids.py A B --output-dir D:\reports\run_01
```

输入重放事件时比较最终发出的叶子：

```powershell
python tools\compare_01_message_ids.py A\01_replace_events.jsonl B\01_replace_events.jsonl --view final
```

`--view` 可取 `live`、`candidate`、`template`、`final`，默认是 `live`。

## 5. 输出文件

| 文件 | 用途 |
|---|---|
| `message_diff.md` | 快速查看消息ID计数和排名靠前的字段候选 |
| `message_id_counts.csv` | 用表格筛选消息ID次数、频率和长度变化 |
| `field_anomalies.csv` | 用表格筛选字段偏移、宽度、A/B值和异常占比 |
| `message_diff.json` | 完整机器可读结果，包含样本值及B侧发生时间/报告序号 |

字段类别：

- `ZERO_TO_NONZERO`：A中该字段全部为0，B中出现非0；
- `STABLE_BASELINE_CHANGED`：A中字段固定，B出现新值；
- `NEW_VALUE_OUTSIDE_BASELINE`：A中取值集中，B出现较多基线未见值。

报告中的“完整叶子偏移”从叶子第一个字节算起；“载荷偏移”从二进制消息的 `0x20` 位置算起。例如：

```text
完整叶子 0x48 == 载荷 +0x28
完整叶子 0x50 == 载荷 +0x30
```

## 6. 当前日志回测示例

用“测试6未封禁”作为A、“测试5快速封禁”作为B，仅比较 `0x0207`，脚本得到：

| 项目 | A | B |
|---|---:|---:|
| 已解密Type9包 | 103 | 44 |
| 总叶子 | 350 | 151 |
| `0x0207`次数 | 3 | 3 |

次数相同，但两个稳定字段发生了变化：

| 完整偏移 | 载荷偏移 | A值 | B值 |
|---|---|---|---|
| `0x48` | `+0x28` | `00000000` ×3 | `0000000D` ×2、`0000001C` ×1 |
| `0x50` | `+0x30` | `00000000` ×3 | `00000001` ×3 |

这说明只统计“有没有 `0x0207`”信息量不足；同一消息ID内部稳定字段的零/非零变化更值得继续做时间线关联。脚本将此类字段排在最前面，同时保留原始计数，避免把候选字段直接等同于最终原因。

## 7. 采样建议

1. A和B尽量来自相同客户端版本、地图、模式和相近对局阶段；
2. A录制时间尽量覆盖至少一整局，让正常动态字段形成足够取值；
3. B只改变一个实验变量，并记录改变发生时间；
4. 先看新增/缺失消息ID，再看同ID同长度的 `ZERO_TO_NONZERO` 字段；
5. 对候选字段结合 `message_diff.json` 中的时间、`report_index` 和 `sequence` 回看原始事件；
6. 至少重复两到三组A/B，确认候选字段可重复出现。
