## 1. 卡住账号的 4/7 拆开

样本（原生 `record_leaves`，禁止用 replay_leaves）：

```text
数据/130/130.7/AI日志/run_20260826_194228_777904/record_leaves.jsonl
game_id = 13000835341849620720
session = 171.88.110.186#1787745115
墙钟零点 = 文件首叶 time_unix_ms
时长 ≈ 1612 s（约 27 分钟）
app_version = v1.130.7
```

读法与 F5 相同：

```text
message_id = raw[0x16:0x18]  big
slot       = raw[0x1C:0x1E]  big
+0x20      = raw[0x20:0x24]  big
elapsed    = (time_unix_ms - 首叶 time_unix_ms) / 1000
```

### 1.1 五档 slot 周期（当前代码：末两档差值必须恰好等于周期）

| ID | 规定周期 | 次数 | unique slots | 末间隔 | 就绪 |
|---|---:|---:|---|---:|---|
| 8007 | 600 | 3 | 60, 660, 1260 | 600 | 是 |
| 800D | 600 | 3 | 60, 660, 1260 | 600 | 是 |
| 802C | 600 | 3 | 30, 630, 1230 | 600 | 是 |
| 800F | 900 | 2 | 60, 960 | 900 | 是 |
| **800A** | **900** | **24** | 见下 | **30** | **否** |

所以 **800A 确实没就绪。** 和 8027/8029 一起，正好 4/7。

### 1.2 800A 实际 slots（本场原生）

```text
60,90,120,150,180,210,240,270,300,330,360,390,420,450,480,510,
然后跳到
1380,1410,1440,1470,1500,1530,1560,1590
```

间隔：

```text
连续 15 个 30
中间一次 870   （510 → 1380）
然后再连续 7 个 30
末两次 1560/1590 差 30  → UI「间隔30/900」
```

注意：中间 **480 → 1380 = 900** 是存在的，但当前就绪算法只看 **排序后末两档**，后面 30-slot 连发把 900 冲掉了。

800F 同场是干净的 `60 → 960`（900），所以 800F 亮、800A 不亮。

这和 F5 之前锁的「800A/800F 都是 900；封禁样本 30-slot 连发不当标准」发生冲突：本场是 **原生录制**，不是重放，800A 就是 30-slot 连发 + 一次约 15 分钟的簇间跳跃。

## 2. 8027/8029：次数够，但 W1 被判不完整

F5 已锁、v1.130.7 已实现：

```text
W1 完整 = 8027 开扫首帧（本波 +0x20 最大且 ≥150）
         + 8027 尾巴 +0x20=59
         + 同波 8029 收齐
W2 只需开扫首帧
T = W2首 elapsed − W1首 elapsed
```

F5 四份对照（D6 / 129绿色 / 129大厅 / 128.8）的短波都是：

```text

一波大约 4～9 条 8027
```

本场卡住账号 **不是这种波**：

### 2.1 8027 两波（43 条，空档 >180s 自然分成两波）

| 波 | 墙钟 | 条数 | 首 +0x20 | 尾 +0x20 | 末长度 |
|---|---|---:|---:|---:|---:|
| W1 | 39.3s → 224.2s（约 3 分钟） | 21 | 70283 | **52810** | 106 |
| 空档 | 224s → 963s（约 12.3 分钟） | | | | |
| W2 | 962.7s → 1155.6s | 21 | 70296 | **52810** | 106 |

整场 **没有任何一条 8027 的 +0x20=59**。最小值就是 52810。

因此 `evaluate_scan_wave_template` 停在 `waiting_wave1`，**连 T 都不会算**。  
若用「空档>180s 且下一波已开扫」来看，T 已经能算：

```text
T ≈ 962.7 − 39.3 = 923.4 s
```

8029 同样两波，各 41 条，首 +0x20 也是 70283，跟 8027 对齐。不是缺 8029。

### 2.2 和「正常」账号的差别

正常账号 8027 只有约 12 次、长度 `106,110,114,118,122…`，能亮 `扫描波 762s`。  
那是 F5 短波（尾巴 59）。本场 43 次是 **另一套长波**（21 片、+0x20 七万降到五万、永不 59）。

次数多不能推出「尾巴=59 已经出现」。

### 2.3 风险

若继续死等 59：

- 短波账号：周期列正常（已验证）
- 长波账号：即使录满两轮、T 清晰，UI 一直 等待完整第一波，重放也不循环第一波

若放开「有 180s 空档 + 下一波开扫就当 W1 完整」：

- 本场能亮、能外推
- 必须继续挡住：孤立 SpringBoard `+0x20=59` 不能当开扫；残波不能当循环源
