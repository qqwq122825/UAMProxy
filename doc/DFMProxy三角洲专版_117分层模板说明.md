# DFMProxy v1.117 分层模板池

> 本文作为 v1.117 历史说明保留。当前正式策略见《DFMProxy三角洲专版_118未知叶子透传说明》；未知叶子默认完整透传。

## 当前录制身份

所有具备录制权限的代理账号统一写入玩家个人录制：

- `player`：玩家个人录制，只为同一游戏用户 ID 提供第一优先级模板。

录制完成后，系统管理员在“录制管理”选中玩家会话并点击“设为官方模板”。系统会
直接把该会话标记为已发布官方模板、生成批次ID，并写入独立官方模板文件。历史版本
导入的 `official` 会话继续兼容。

## 重放顺序

1. 查找当前玩家、兼容客户端版本的个人模板。
2. 当前叶子个人模板未命中时，查找兼容版本的已发布官方模板。
3. 两级模板都没有 `recordCode + messageId + length` 结构时，完整保留该实时叶子并写入未知结构日志。
4. 只替换已命中的叶子；继承实时序号、计数、时间和会话字段，并更新明文 CRC、密文长度、外层 CRC 和物理分片。
5. 重新解密并执行帧校验，通过后输出；过程写入 01 专属分析日志。

官方样本带 `source_priority=1`，玩家样本为 `0`。同一结构同时存在时，叶子选择器先比较来源优先级，再比较实时序号距离。

## 官方模板生命周期

```text
玩家正常录制 → 管理员选中会话 → 设为官方模板 → 重放只读
```

已发布官方模板不参与一天自动清理，并单独保存到：

```text
C:\PyProxyApp\OfficialTemplates\dfm_official_templates_v117.json
```

软件启动时自动加载该文件。设置官方模板、导入数据和软件退出时，都会原子更新持久文件；同时保留 `C:\PyProxyApp\v117_recording_pools.json` 作为玩家与官方数据的完整恢复快照。

“导出”可选择已发布官方模板包、完整备份或仅玩家录制。官方模板包采用 v7 格式，只携带已发布官方01模板；导入后保持发布状态，并按 `batch_id + donor游戏ID + client_version` 去重。

每次游戏更新创建新的客户端版本批次。配置为明确版本时，只选相同版本或标记为 `auto` 的兼容录制。

## 日志判断

录制生命周期持续追加到：

```text
C:\PyProxyApp\01RecordPackets\01_record_sessions.jsonl
```

其中包含代理账号、游戏ID、玩家/官方角色、批次、版本、01/33数量和发布状态。

每次重放启动目录增加：

```text
template_selection_events.jsonl
template_usage_events.jsonl
```

前者直接判断无个人录制的玩家是否选择了官方池；后者记录每个报告实际使用的玩家叶子、官方叶子和未知实时叶子数量。两个精简文件覆盖所有重放代理账号，完整包级分析仍保留原有 `test` 专项日志。

叶子结果中的关键字段：

- `template_scope=player`：来自玩家个人池。
- `template_scope=official`：个人池未命中后使用官方模板。
- `replacement_level=UNMATCHED_LEAF_PASS_LIVE`：两级模板未命中，完整保留实时叶子。
- `unmatched_pass_live_leaves`：本报告保留的未知实时叶子数量。
- `reason=UNMATCHED_LEAF_PASS_LIVE`：整份报告没有可变化的已知叶子，最终原样发送实时报告。
- `pruned_leaves`：仅专项裁剪实验的删除数量，默认应为 `0`。

普通日志中的 `01_unknown_leaf_samples.jsonl` 每种结构最多保存三份原始叶子；`01_unknown_context_samples.jsonl` 同步保存对应的完整01物理帧和完整 Type9 明文。独立根记录或整个报告均无任何已知兄弟叶子时同样保持实时报告。

默认策略不裁剪未知叶子。需要做受控单变量实验时，完整的双叶子裁剪前后 HEX、长度计算、递归重建伪代码、空批次保护和 CRC 更新顺序见：

```text
../DFMProxy三角洲01协议对抗教程.md
第17节：v1.117 未命中叶子裁剪完整实例
```

当前默认流程为：

```text
实时叶子
→ 玩家模板精确匹配
→ 玩家未命中时查已发布官方模板
→ 两级基础结构均未命中的叶子保留完整实时字节
→ 限量记录原始叶子、完整Type9明文和完整01物理帧
→ 仅替换已命中的叶子并保持原始子项数量、顺序和长度
→ 重算 Type9 明文CRC并重新加密
→ 重建01物理帧和外层CRC
→ 解密回验通过后发送；无实际变化时原样透传
```
