## 0. 现场

录制「消息目录」里，核心 80xx 已见也会出现 `—`。例如：

| ID | 次数 | 当前「周期状态」 |
|---|---:|---|
| 8000 | 1 | `—` |
| 8002 / 8003 | 已见 | `—` |
| 8004 | 9 | `子型 9/9` |
| 8007 | 1 | `等待第2次 (1/2)` |

用户要求（已升级为硬规则）：

- **所有 80xx 重建用的周期都必须写清楚，一行都不能 `—`。**
- 有周期的写周期数字；**语义上只发一次的写 `一次性`**；跟配置的写配置档。
- 禁止把「本场只录到 1 次」当成一次性。8000 本场 1 次仍是 `默认 600-slot`，因为重建按 600 走。
- `—` = 操作员会当成「没有周期」。因此 `—` 只允许出现在非 80xx 辅助行。

---

## 1. 为什么现在是 `—`

这一列目前只渲染两类：

1. **7 项玩家周期就绪**（计入 `n/7`）：`8007/800A/800D/800F/802C` + `8027/8029`
2. **8004 子型** `x/9`

其余核心 80xx（中央九类、800C/8023/8024/8025/802A/802B）以及同表里的 `8C03` 都走 `else: "—"`。目录里已知 80xx 共 **22 个**（21 个核心 + `8C03`）。

这不是 8000 没有周期。中央模型里 **8000 默认就是 600 slot、首档 30**（`BUILTIN_MODEL[0x8000]`：`first_slot=30, period=600`）。重放不靠玩家录制去确认 8000 的周期，所以录制 UI 以前不展示。

**禁止把「写上默认周期」理解成：8000 计入 7/7，或玩家模板要满两档才外推 8000。** 中央九类继续由中央模型生成。

## 2. 【Cursor】草案：所有 80xx 这一列怎么写

硬规则：

- **`0x8000`～`0x8FFF` 禁止渲染 `—`。** 实现验收：详情表里所有 `80xx` 行该列都有字。
- **这一列写的是重建用的周期，不是本场出现次数。** 四类文案：
  1. **有周期** → `默认 N-slot` / 玩家就绪进度（`✓ 600-slot` 等）
  2. **语义上只发一次** → `一次性`（8023/8025；8024 并写开机域）
  3. **跟配置** → `跟随配置 · 当前档`（802A/802B）
  4. **会多次出现但没有稳定 slot 钟** → `无稳定周期`（800C）
- **7 项就绪进度保持现状**（等待第 2 次 / ✓ 600-slot / 等待第 3 簇 / ✓ 扫描波 Ts）。这列继续驱动 `n/7`。
- **有默认 slot 钟的：写 `默认 N-slot`**，即使本场只录到 1 次。8000 录 1 次 ≠ 一次性。
- **802A/802B 写 `跟随配置` 并带当前档。** 这对叶重放跟配置页「对局数据 802A/B」，不是 slot 钟，也不是一次性。
- **8C03 也是 80xx，不能 `—`。** 条件强检，默认 120-slot、首档 150。
- **非 80xx 辅助行**（100x / 9000 / 9100 / FFFB 等）本轮可以继续 `—`。不是本轮范围。
- 不改 `periodic_total=7`。不改重建算法。不要伪造 600，也不要用冻死的 13398。
