# DFMProxy v1.129.0 操作与状态审计说明

## 目标

让一份 `AI日志/run_*` 自带运行期间的操作证据与状态快照，区分“规则实际改写”“统计被清零/重载”“配置位中途变化”和“界面当前显示”四类事实。

## 新文件

`control_events.jsonl`，schema 为 `dfm-ai-control-event-v129-v1`。每行包含：

- `time/time_unix_ms/run_elapsed_ms`：墙钟时间与本次运行相对时间；
- `source/actor/action/phase`：事件来源、执行者、动作与前后阶段；
- `details`：按钮、配置差异、规则ID、计数前后值、重载原因；
- `state`：代理运行状态、3366状态、关键配置位、热规则generation/revision/成功计数及运行计数。

`manifest.json` 新增：

- `app_version=v1.129.0`
- `control_audit_revision=v129-operation-state-audit-r1`
- `files.control_events=control_events.jsonl`

## 记录范围

1. 所有主界面按钮点击：按钮文本、对象名、勾选状态和点击后的完整状态；
2. 配置变化：逐字段记录 `before/after`，覆盖补数据、全额重建、01只收录、详细日志、官方模板回退、自动结束、下发处理和端口等关键位；
3. Type9热规则：bootstrap、强制重载、文件变化自动重载、导入替换、重载失败；
4. 成功改写计数：每次递增记录 `rule_id/before/after/generation`；
5. 计数清零：记录清零前后的整张计数表；
6. 代理运行：启动、监听器初始化、停止、手动3366开关变化；
7. 周期快照：界面运行期间每60秒写一次完整状态。

## 快速分析

```bash
python tools/analyze_ai_logs.py "C:\\PyProxyApp\\AI日志\\run_*"
```

输出的 `control_audit` 会列出动作统计、来源统计、每条热规则的实际递增次数、最后状态及最近500条操作时间线。

例如判断 `1105`：

- `replay_leaves.jsonl` 证明叶子是否命中、网络输出是否改写；
- `control_events.jsonl` 中 `hot_rule_success_counter_increment` 证明计数何时由N变成N+1；
- `hot_rule_generation_installed` 证明哪次重载建立了新generation并重置计数；
- `hot_rule_success_counters_cleared` 证明是否点过清空；
- 周期状态快照证明当时界面、配置与规则代次。
