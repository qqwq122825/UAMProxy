# DFMProxy v1.130.1 条件强检补发与日志清理说明

## 本版改动

1. 录制管理显示设备型号、系统版本和稳定设备指纹，便于确认同设备换账号模板。
2. 新增条件强检中央层：
   - Live出现`mrpcs_i_j.data + mrpcs_i_f.data`后启用`0x8C03`；
   - Live出现`mrpcs_i_vv.data + mrpcs_i_v_tl.data`后启用`0x9100`；
   - 普通会话保持关闭，Live同slot优先，迟到重复叶转换为保序空`0x2000`。
3. `0x8C03`按首slot 150、120-slot周期补发，重建完整logical slot和轮次计数。
4. `0x9100`按首slot 600、600-slot周期补发，正文使用已验证固定状态体。
5. AI日志新增`v130_central_strong`输出来源及强检文件、激活ID、激活slot、补发ID状态。
6. 配置页新增“清空AI日志”，运行中清理后立即轮换到新`run_*`；录制池、官方模板与配置保持原状。

## 样本回溯

- 第一份强检长录制：`0x8C03`为150～1470、间隔120；`0x9100`为600/1200。
- 第二份强检长录制：`0x8C03`为150～1710、间隔120；`0x9100`为600/1200。
- 第二份样本在slot 870与990之间发生网络重连，原生叶序号和两个强检周期均连续，验证调度状态应按游戏进程继承。

## 重放测试观察点

1. 打开补数据模式；全额重建开关对条件强检中央层无影响。
2. 清空AI日志后启动重放，保持游戏运行至少22分钟。
3. 在`replay_groups.jsonl`中查找`layer=central_strong`。
4. 在`replay_leaves.jsonl`中确认：
   - `0x8C03`从slot 150开始，每120 slot一次；
   - `0x9100`在slot 600、1200出现；
   - `recordSequence`连续，输出机械校验通过。
5. `manifest.json`应显示`app_version=v1.130.1`和模型修订`v130.1-conditional-strong-profile-r1`。
