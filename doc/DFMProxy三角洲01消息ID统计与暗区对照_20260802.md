# DFMProxy 三角洲 01 消息 ID 统计与暗区对照

> 统计日期：2026-08-02
> 三角洲样本版本：v1.114
> 目的：建立三角洲专属 `messageId` 字典，同时明确 TerSafe 公共叶子格式与游戏专属正文之间的边界。

> 2026-08-05增量结论与当前重放动作见
> [v1.121 Type9重点消息ID语义与重放策略](DFMProxy_v121_Type9重点消息ID语义与重放策略_20260805.md)。
> 2026-08-15：`0x8027`/`0x8029`/`0x9000` 已确认为一条叶子一个进程或包名；
> 内容黑名单删叶见 `数据/125.1/125.1_80xx与进程黑名单删叶报告_20260815.md`。

## 1. 结论

三角洲与暗区复用了同一套 TerSafe 明文记录容器：

```text
01 物理帧
└─ 01 0A 00 09 Type9 加密记录
   └─ 解密明文记录
      ├─ 0x010A001B：批量容器
      └─ 0x0102000A：带 messageId 的二进制叶子
```

公共记录头、批量容器和 `0x0102000A` 消息头可以共用解析器，但以下内容必须按游戏维护：

```text
messageId 字典
messageId 对应的正文长度和字段布局
检测 Task 产生的结果结构
动态计数器、时间、会话和阶段字段
```

因此跨游戏的完整匹配键应至少包含：

```text
game + recordCode + messageId + actualLength + subtype
```

不能只凭 `messageId` 判断正文语义。

## 3. 公共叶子格式

### 3.1 所有内部记录的公共头

| 偏移 | 长度 | 类型 | 含义 |
|---:|---:|---|---|
| `0x00` | 4 | BE32 | 结构版本，当前常见为1 |
| `0x04` | 2 | BE16 | 本条记录总长度 |
| `0x06` | 4 | BE32 | `recordCode` |
| `0x0A` | 4 | BE32 | `recordSequence`，运行期递增 |
| `0x0E` | 变长 | - | 按 `recordCode` 继续解析 |

### 3.2 `recordCode=0x0102000A` 的公共消息头

| 偏移 | 长度 | 类型 | 含义 |
|---:|---:|---|---|
| `0x0E` | 8 | BE64 | 消息体长度 |
| `0x16` | 2 | BE16 | `messageId` |
| `0x18` | 2 | BE16 | 协议常量/消息头字段 |
| `0x1A` | 2 | BE16 | 平台或消息族候选 |
| `0x1C` | 2 | BE16 | 魔数/协议字段 |
| `0x1E` | 2 | BE16 | 消息版本 |
| `0x20` | 变长 | - | 游戏、版本和检测 Task 专属正文 |

“叶子格式相同”指以上容器和消息头可以递归解析，不表示 `0x20` 后的正文跨游戏相同。

- **已确认**：可读字符串、稳定字段边界或多样本差分共同支持；
- **候选**：存在稳定相关性，尚缺少字段构造点或协议字段名；
- **未知**：目前只完成结构、次数和长度统计。

## 5. `0x8027` 与 `0x8029`

### 5.1 `0x8027`：活动进程/应用枚举

一条叶子只带一个进程名、一个 Bundle ID 和一处 `BackBoardServices` 来源，不是一条消息里枚举多个进程。多进程表现为多片叶子，可与 `0x800A` 同包。

数据10统计：

```text
录制：14条，14组进程/Bundle组合
重放：44条
```

正文中可稳定提取：

```text
进程或显示名称
Bundle Identifier
BackBoardServices: <redacted> + 280
```

录制示例：

```text
DeltaForceClient / com.tencent.tmgp.dfm
WeChat / com.tencent.xin
Shadowrocket / com.liguangming.Shadowrocket
Aweme / com.ss.iphone.ugc.Aweme
PosterBoard / com.apple.PosterBoard
```

### 5.2 `0x8029`：进程与调用位置采样

数据10统计：

```text
录制：36条，32组唯一进程/位置组合
重放：121条
```

正文包含进程名以及模块、符号或模块内偏移，例如：

```text
DeltaForceClient / GameController: <redacted> + 152
DeltaForceClient / CoreMotion: ... + 5580
backboardd / CoreFoundation: <redacted> + 28
backboardd / backboardd + 50480
locationd / locationd + 7218796
```

它与 `0x8027` 是两个消息ID：前者偏向活动应用身份，后者偏向进程调用位置或栈来源摘要。

## 6. 与暗区的对照

暗区依据：

```text
/Users/xxx/Documents/调试/tersafe模块分析/网络分析/01解密明文字段分析.md
/Users/xxx/Documents/调试/tersafe模块分析/网络分析/暗区与三角洲_0x8024结构核对_20260801.md
/Users/xxx/Documents/调试/tersafe模块分析/网络分析/实验归档/
  study-troll-draw-20260801/T1_同进程绘制开关差分/run1/分析输出/analysis-01/summary.json
```

| 三角洲 | 三角洲语义 | 暗区ID | 暗区语义 | 对照结论 |
|---|---|---|---|---|
| `0x8027` | 活动进程名、Bundle ID、来源 | `0x8418` | PID、进程名、Bundle ID、来源及尾部属性 | 高度相似的传感器，ID不同 |
| `0x8029` | 进程与模块/符号/偏移 | `0x8217` | 已加载Framework/模块完整路径 | 同属模块环境采样，但正文不是一一对应 |
| `0xFFF2` | tersafe框架路径 | `0xFFF2` | tersafe框架路径 | ID与大类语义一致 |
| `0x8024` | 44字节，三个时间/会话值 | `0x8024` | 60字节，XOR-B6文本 `module_count==0` | ID相同，正文与语义不同 |
| `0x9000` | 安装应用/环境目标探测 | 暗区由 `0x8418` 等记录覆盖相关应用信息 | 活动应用/进程枚举 | 传感器组合不同 |

暗区现有分析输出没有出现三角洲的 `0x8027`、`0x8029`。暗区进程枚举主要使用
`0x8418`，模块路径主要使用 `0x8217`。因此不能建立“一个TerSafe消息ID对应一个全球固定语义”的字典。

### `0x8024` 是最明确的反例

```text
公共 version/length/recordCode/recordSequence：同格式
recordCode：两边都是 0x0102000A
messageId：两边都是 0x8024
三角洲 actualLength：44
暗区 actualLength：60
三角洲正文：时间/会话状态
暗区正文：module_count==0 检测任务结果
```

这证明解析分派至少要加入游戏和长度，Task更新后还应加入客户端版本或正文子类型。

## 8. DFMProxy当前字段策略索引

当前规则集：

```text
v1.117-tiered-template-v1
```

必须继承实时值的主要字段：

| messageId | 实时字段 |
|---|---|
| `0x1001` | `+0x20..0x23` 会话启动时间 |
| `0x1003` | `+0x26..0x27` session word |
| `0x1005` | `+0x28..0x2B` runtime value |
| `0x100A` | `+0x20`及多份计数副本、`+0x40`事件时间 |
| `0x100E` | `+0x20` cycle、`+0x24` tick |
| `0x1105` | `+0x20` report counter |
| `0x2001` | `+0x20` fixed step counter |
| `0x8004` | `+0x1C..0x1D` group id |
| `0xFFFB` | `+0x28` report counter |
| `0x0101/0x0102/0x0103` | `+0x20` step counter |

强动态完整实时保护：

```text
recordCode == 0x01122388
messageId == 0xFFF2 或 0xFFF3
录制与实时 recordSequence 距离 > 128
录制与实时十位时间戳差值 > 30秒
```

`0x8024`、`0x8030`、`0x80CC`、`0x80CD` 属于重点观察ID，会记录完整差分；其中
`0x8024` 在三角洲已经确认包含实时时间，因此后续规则不得照搬暗区的60字节正文解释。

## 9. 后续更新原则

1. 每款游戏维护独立 `messageId` 注册表；
2. 新ID先记录 `recordCode/messageId/length/subtype/count`，不直接套用其他游戏语义；
3. 同ID出现新长度时视为新结构分支；
4. 对连续多包识别所有计数副本、时间、会话和阶段字段；
5. 可读字符串只作为内容证据，字段名需要多样本差分或构造点验证；
6. 游戏或检测 Task 更新后重新生成长度与频率基线；
7. 跨游戏只共享拆包、Type9解密、递归叶子和CRC逻辑。
