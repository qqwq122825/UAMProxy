# 01 数据快速对比脚本使用说明

## 推荐入口：批量对比

脚本：`tools/quick_compare_01_suite.py`

第一份参数作为正常基线，后面的每一份数据分别与基线比较。待检查数据是重放 `run_*` 时，还会自动生成一份 `Live → Final` 审计，显示代理实际删除或替换了哪些消息和字段。

```bash
python3 tools/quick_compare_01_suite.py \
  BASELINE/01RecordPackets \
  NEW_DATA/01ReplayAnalysis/run_RUN_ID \
  --baseline-label 正常录制 \
  --output-root NEW_DATA/快速对比结果
```

一次比较多场：

```bash
python3 tools/quick_compare_01_suite.py \
  BASELINE/01RecordPackets \
  NEW_DATA/run_1 \
  NEW_DATA/run_2 \
  NEW_DATA/run_3 \
  --output-root NEW_DATA/批量对比结果
```

只关注指定消息：

```bash
python3 tools/quick_compare_01_suite.py BASE RUN \
  --message-id 0x0207 \
  --message-id 0x100C \
  --message-id 0x8028 \
  --message-id 0x8002
```

## 输出文件

顶层：

- **`AI_REVIEW.md`：给 AI 先看的对比文档。** 先列消息ID新增/缺失，再按同一消息ID列出字段差；时间戳和60Hz时钟已加白。
- `comparison_index.md`：所有场次的快速结论。
- `comparison_index.json`：机器可读结论和完整来源路径。

每个对比子目录：

- `message_diff.md`：消息ID、频率、长度、字段异常表。
- `message_diff.json`：完整证据，包含输入路径、视图、样本数和异常样本时间。
- `message_id_counts.csv`：每个消息的A/B次数、每100包频率、新增长度。
- `field_anomalies.csv`：逐字段变化结果。

索引现在分两块：

- **重点消息**：默认固定看 `0207/1007/1008/100C/100F/8002/8028`，只要字段有异常就列出，不被总分挤掉。
- **按分数排序的前10**：仍可能被时钟/噪声占满，不能只看这一块。

```bash
python3 tools/quick_compare_01_suite.py \
  '数据/125.4/5/01RecordPackets' \
  '数据/125.4/5/01ReplayAnalysis/run_20260816_014856_121103' \
  '数据/125.4/6:沿用5的录制数据/01ReplayAnalysis/run_20260816_031458_534810' \
  --baseline-label '125.4-5录制' \
  --output-root '数据/125.4/5/快速对比_重点消息'
```

用户丢来“这份录制和这份重放对比一下”时，先跑上面的命令，再把 `AI_REVIEW.md` 交给 AI。不要只看按分数排序的前10行。

白名单只收已经坐实的字段，见 `tools/compare_01_field_whitelist.py`：

- `0x2001 +0x20`：60Hz 时钟
- `0x8024` 整叶：时间戳

`0x2001 +0x24`（写视角计数）和 `0x100C +0x50` **不加白**。

状态含义：

- `NEW_IN_B`：新数据新增消息ID。
- `MISSING_IN_B`：新数据缺失消息ID。
- `FREQUENCY_SHIFT`：按每100包归一化后频率变化达到2倍或降至一半。
- `ZERO_TO_NONZERO`：基线字段全0，新数据出现非0。
- `STABLE_BASELINE_CHANGED`：基线值固定，新数据出现其他值。
- `NEW_VALUE_OUTSIDE_BASELINE`：新数据出现基线取值集合之外的新值。

## 精确两份数据比较

脚本：`tools/compare_01_message_ids.py`

### 正常录制与重放Live

```bash
python3 tools/compare_01_message_ids.py \
  BASELINE/01RecordPackets \
  NEW_DATA/01ReplayAnalysis/run_RUN_ID \
  --view-b live \
  --label-a 正常录制 \
  --label-b 重放Live \
  --output-dir NEW_DATA/录制_vs_Live
```

### 同一场重放的Live与最终发送结果

```bash
python3 tools/compare_01_message_ids.py \
  NEW_DATA/01ReplayAnalysis/run_RUN_ID \
  NEW_DATA/01ReplayAnalysis/run_RUN_ID \
  --view-a live \
  --view-b final \
  --label-a Live \
  --label-b Final \
  --output-dir NEW_DATA/Live_vs_Final
```

这个对比会直接显示：

- `0207 drop_leaf` 后 Final 中是否消失；
- `100C` 是否使用模板值；
- `8028 +0x24`、`8002 +0x2C` 是否由非0变成0；
- 其他消息是否被意外改变。

### 只看一个消息

```bash
python3 tools/compare_01_message_ids.py BASE RUN \
  --message-id 0x100C \
  --output-dir RESULT/100C
```

## 切点和计数器时间线

脚本：`tools/compare_01_counters.py`

```bash
python3 tools/compare_01_counters.py NEW_DATA/run_RUN_ID \
  --cut 175 \
  --watch 8028,8002,100C,0207,100F,1008,1007
```

脚本：`tools/compare_01_cutpoint.py`

用于输出启动追踪前后的秒级变化、首次非零时间和候选/最终值。

## 输入路径注意点

- 比较原始录制时传入具体 `01RecordPackets` 目录。
- 比较重放时传入具体 `01ReplayAnalysis/run_*` 目录。
- 高层数据目录同时包含录制与重放时，解析器优先读取录制目录；传入具体子目录可以让来源保持明确。
- 报告中的 `A输入/B输入` 和 `view=live/final` 用于复核实际读取对象。

## 125.4 示例

```bash
python3 tools/quick_compare_01_suite.py \
  '数据/125.4/5/01RecordPackets' \
  '数据/125.4/6:沿用5的录制数据/01ReplayAnalysis/run_20260816_031458_534810' \
  --baseline-label '125.4-5正常录制' \
  --output-root '数据/125.4/快速对比_5录制_vs_6重放_20260816'
```

该示例已经生成结果，可直接用作下次数据的目录结构参考。
